# 网页设计 · 技能目录

这个目录同时存放三样东西，**必须始终一致**：

```
skills/网页设计/
  index.html          索引页（脚本生成，禁止手改）
  previews/           各技能的预览动图副本
    <技能目录名>.gif
  README.md           本文件：维护规则
  NN-<中文名>(<目录名>).zip   技能包本体
```

`index.html` 可以直接双击打开，也可以在 GitHub 上点开看。它是这个分类的**唯一总览**。

## 维护规则（硬性）

> 一句话：**新增或修改任何一个网页设计技能，索引、预览图、技能包三者必须同一次提交里一起更新。少一样就是没做完。**

### 1. 新增技能时必须同时更新索引

往 `roster.json` 加一条并设 `"category": "网页设计"` 之后，**必须**重新生成索引：

```bash
python3 tools/build_web_index.py
```

这条命令会：
- 按 roster 里 `category=网页设计` 的技能重建 `index.html`（仓库 + 本地副本两处）
- 把每个技能包的 `preview.gif` 复制成 `previews/<技能目录名>.gif`
- 删掉已经没有对应技能的孤儿图

**不允许手改 `index.html`**——下次重建会被覆盖，而且一定对不上。

### 2. 每项技能必须有 `preview.gif`

放在**技能包根目录**（与 `SKILL.md` 同级）。没有预览图的技能，索引里会显示成红色占位块，检查命令直接判失败。

规格上限：

| 项 | 要求 | 为什么 |
|---|---|---|
| 宽度 | **≤ 320 px** | 卡片里按 144px 显示，320 正好 2 倍图 |
| 帧率 | ≤ 20 fps | 再高体积涨得比观感快 |
| 文件 | ≤ 800 KB | 单个包要留出 5 MiB 解压上限的余量 |
| 首帧亮度 | **> 200** | 黑屏开场当缩略图就是一块黑的，等于没有 |
| 内容 | **该技能最综合的效果** | 不是随便截一帧；交互类要录到真实操作过程 |

高度不限，但建议 180–222（与宽度搭配出接近 3:2 的比例，适配卡片框）。

### 3. 预览图要「演」出这个技能

反面例子（都被打回过）：

- 静态页截一帧当 GIF → 不叫预览
- 技能默认是静态模式，直接录 → 录出来是死图，必须先开动效（archify 要先把 `#btn-motion` 从「静态」切到「动态」）
- 用上游素材里首帧发黑的 GIF → 亮度 14，缩略图全黑

正确做法：找到该技能最能代表它的一句话，把这句话对应的**那一个动作**录完整——从起始态到结束态，能循环。

### 4. 提交前必须过一致性检查

```bash
python3 tools/check_web_index.py
```

它核对六件事，任何一项不过就以非 0 退出：

1. roster 里 `category=网页设计` 的技能集合 == 索引里列出的集合
2. 每个技能包的 `preview.gif` 存在
3. `previews/<目录名>.gif` 与包内 `preview.gif` 的 **md5 一致**（防止复制错、忘记重建）
4. `previews/` 里没有孤儿图
5. 每张 GIF 的宽度 / 体积 / 首帧亮度达标
6. 仓库副本与本地副本内容一致

标准流程：

```bash
python3 tools/build_web_index.py && python3 tools/check_web_index.py
```

**检查不通过就不要推仓库。**

### 5. 改名或移除技能时，旧资源一起清

技能改名 → 旧目录名的 `previews/<旧名>.gif` 必须删掉；技能移出网页设计分类 → 索引里那一项和它的预览图一起删。
`build_web_index.py` 会自动清孤儿，但**改完要跑一次**，别假设它自己会动。

### 6. 分类归属以 `roster.json` 为准

`category` 字段是唯一事实来源。技能自己的 `manifest.json` 里也有一份 `category`，两边要一致；
`manifest.json` 那份用于分发后自查，`roster.json` 那份用于生成索引与目录结构。

## 预览 GIF 怎么造

本机没有 ffmpeg 的 GIF 编码器（Playwright 自带的那份是精简构建），所以走纯 JS 链路：

```
Playwright 截 PNG 帧 → pngjs 解码 + 面积平均缩放 → gifenc 量化编码
```

两个关键点：

- **确定性时间轴**：自己写 `render(t)` 纯函数，任意 t 都能算出确定的一帧，再用 `window.seek(t)` 逐帧截图。比 `requestAnimationFrame` 录屏稳。
- **背景别做持续漂移**：全画面每帧都在变，GIF 体积翻倍；主角是谁就让谁动。

成品自检（三件套，都是纯 JS）：

- 帧拆出来看：`gifframe.mjs <gif> <帧号> out.png`
- 首帧亮度：`check_web_index.py` 会报，低于 200 会警告
- 尺寸超了就减宽/隔帧，别降色数（色数对渐变图几乎没用）
